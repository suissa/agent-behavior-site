---
title: Agent Behavior
description: A behavior-first execution model for semantic Agents, derived Skills, Actions, persistent Knowledge, and MCPQ communication.
---

Agent Behavior defines a portable execution model in which the Agent is the first-class semantic unit.

The central rule is:

> Every semantic Agent instance has an Agent Skill derived from its Behavior Flow.

The filesystem package is the portable projection of that model:

    Agent
    ├── agent.json
    ├── SKILL.md                 # derived Agent Skill
    ├── actions/                 # executable capabilities
    │   └── <action>/SKILL.md
    ├── knowledge/               # evidence, wiki, evolution
    └── mcpq.json                # communication channels

## Why this model exists

Agent Skills standardized a useful portable primitive: SKILL.md plus optional scripts, references, assets, and progressive disclosure. Agent Plugins standardized packaging around Skills and MCP servers. WikiSkill demonstrated how persistent knowledge can support controlled skill evolution. MCP Tasks now provides official durable asynchronous task semantics.

Agent Behavior combines these ideas but changes the semantic center.

The important distinction is not a directory rename.

It is:

    Skill       = behavioral definition / projection
    Action      = executable capability
    Agent       = semantic execution unit
    Actor       = concrete execution identity
    Runtime     = execution environment

## Complete semantic chain

    Intent
      ↓
    Behavior Flow
      ↓
    AtomicSkill → AtomicBehavior → Action
                                  ↓
                                Agent
                                  ↓
                                Actor
                                  ↓
                               Runtime
                                  ↓
                              Trajectory
                                  ↓
                               Evidence
                                  ↓
                                 Wiki
                                  ↓
                              Evolution
                                  └──→ validated Behavior Flow change
                                             ↓
                                      derived Agent Skill

This gives one model for execution, testing, observability, knowledge, and controlled evolution without treating every log, prompt, or Skill file as the same semantic object.

## What is portable

Agent Behavior standardizes the package boundary and the portable projections:

- Agent identity;
- root Agent Skill;
- Action discovery;
- Agent Skills-compatible SKILL.md mechanics;
- Knowledge boundaries;
- MCPQ channel configuration;
- narrow failure isolation;
- Actor/Runtime responsibility boundaries.

The semantic source may live in a separate Semantic-as-Code layer. This draft does not force one DSL for Behavior Flow.

## Queue-first communication

MCPQ is the Agent communication boundary.

Queue is the default because Agent execution can be asynchronous and durable. Work may need retry, delayed execution, fan-out, human healing, or resumption.

MCP remains available for interoperability, and MCP Tasks can provide durable asynchronous task handles where supported.

## Knowledge is not behavior

A critical boundary is:

    Evidence ≠ Wiki ≠ Active Skill

Evidence records what happened.

Wiki stores what was learned from it.

The active Agent or Action Skills represent what the Agent is currently expected to do.

Evolution connects these layers through an explicit validation gate.
