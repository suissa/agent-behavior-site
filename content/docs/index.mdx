title: Agent Behavior
description: A portable execution model for Agents with behavioral skills, Actions, persistent knowledge, and MCPQ channels.
---

Agent Behavior defines a portable unit of executable agent behavior.

The primary unit is an Agent, not a plugin. An Agent is an Actor with an identity, a behavioral SKILL.md, executable Actions, persistent knowledge, and communication channels. The format is designed to be portable across runtimes while remaining explicit about what is normative and what belongs to a particular client.

## Why this specification exists

Agent Skills solved an important packaging problem: reusable expertise can be represented as a directory containing SKILL.md, scripts, references, and assets. Agent Plugins extended that idea by defining a portable package containing Skills and MCP servers.

Those specifications describe valuable primitives, but they do not define the complete semantic unit of an executable Agent.

Agent Behavior makes the Agent itself the unit of composition:

    Agent
    ├── SKILL.md              # Agent-level behavior
    ├── actions/              # Executable capabilities
    │   └── <action>/SKILL.md
    ├── knowledge/            # Evidence, wiki, evolution state
    └── mcpq.json             # Communication channels

## The semantic distinction

An Agent Skill is a portable resource that teaches an agent how to perform a capability.

An Agent Behavior Skill is the behavioral contract of an Agent or Action: the durable description of how that execution unit should behave, decide, recover, and interact.

The same SKILL.md mechanics are intentionally reused where possible, but the semantic role is different.

Agent = Actor and execution identity.

SKILL.md = behavioral definition of that Agent or Action.

Action = executable capability exposed by the Agent.

Knowledge = persistent experience and learned knowledge, kept separate from the active behavioral instructions.

MCPQ = channel boundary for Agent communication; Queue is the default mode, with MCP available as an interoperable protocol mode.

## What is incorporated

The specification is deliberately cumulative:

- Agent Skills contributes the portable SKILL.md format and progressive disclosure model.
- Agent Plugins contributes portable package discovery, manifests, fixed component locations, MCP configuration, and narrow failure isolation.
- WikiSkill contributes the separation of raw experience, persistent wiki knowledge, executable skills, proposal loops, and validation-gated promotion.
- This specification adds Agent identity, Action semantics, Agent-level Skills, explicit knowledge lifecycle, MCPQ channels, and runtime-oriented composition.

It is therefore best understood as a semantic superset in scope, rather than a claim that every external implementation detail is reproduced byte-for-byte.

## Minimal Agent

    sales-agent/
    ├── agent.json
    ├── SKILL.md
    ├── actions/
    │   └── create-order/
    │       └── SKILL.md
    └── mcpq.json

The runtime reads the manifest, loads the Agent Skill, discovers Actions, and establishes the declared MCPQ channels. Missing optional components do not invalidate independently valid components.
