title: Runtime conformance checklist
description: Minimum behavior required for an Agent Behavior runtime.

---

This checklist is non-normative. The complete specification governs when wording differs.

## Semantic model

- [ ] Preserve the distinction Intent → Behavior Flow → Trajectory.
- [ ] Preserve AtomicSkill → AtomicBehavior → Action → Actor → Runtime boundaries.
- [ ] Treat the root Agent Skill as derived from the Agent's Behavior Flow.
- [ ] Preserve semantic source and Skill provenance when available.

## Package

- [ ] Load an Agent from a directory.
- [ ] Enforce the filesystem-resolved Agent boundary.
- [ ] Validate agent.json against a locally supported schema.
- [ ] Require the root SKILL.md.
- [ ] Require root Skill name to match agent.json name.
- [ ] Validate Agent Skill frontmatter using the portable Agent Skills rules.

## Actions

- [ ] Discover Actions only from actions/.
- [ ] Validate each Action independently.
- [ ] Require Action Skill name to match its directory name.
- [ ] Preserve scripts, references, and assets as Action-local resources.
- [ ] Continue loading after an independent Action fails.
- [ ] Do not recursively invent Actions.

## Knowledge and evolution

- [ ] Keep Evidence separate from active Skills.
- [ ] Keep Wiki knowledge separate from active runtime instructions.
- [ ] Retain rejected evolution proposals.
- [ ] Enforce the configured validation gate before promoting learned behavior.
- [ ] Prefer semantic Behavior Flow changes followed by Skill regeneration.

## Trajectory and testing

- [ ] Preserve correlation between Intent, Behavior Flow, Actions, and observed Trajectory.
- [ ] Allow validation against payloads, events, state changes, outputs, errors, recovery, and final outcome when the runtime exposes them.
- [ ] Do not treat raw telemetry as active behavior.

## MCPQ

- [ ] Load mcpq.json when present.
- [ ] Default an unspecified channel type to queue.
- [ ] Validate each channel independently.
- [ ] Implement the queue guarantees actually advertised.
- [ ] Follow MCP protocol semantics for MCP channels.
- [ ] Preserve correlation, causation, authorization, and execution identity across asynchronous work.

## Security

- [ ] Enforce path containment.
- [ ] Apply trust and permission policy before executing scripts or external side effects.
- [ ] Isolate secrets from Skills, Actions, traces, queues, and persistent knowledge.
- [ ] Provide sufficient provenance and audit information for learned behavior changes.
