---
title: Agent Skills and Actions
description: Understand how Agent Skills become the behavioral and executable layers of an Agent.
---

Agent Skills provided the file-level primitive that this specification reuses: a directory centered on SKILL.md with optional scripts, references, and assets.

The semantic model here is different.

## Agent Skill versus Action Skill

The root SKILL.md describes the Agent as a whole.

An Action directory contains its own SKILL.md and describes one executable capability.

    Agent
    ├── SKILL.md
    └── actions/
        ├── create-order/
        │   └── SKILL.md
        └── cancel-order/
            └── SKILL.md

This means a Skill is not the same thing as an Action. The Skill is the behavioral contract; the Action is the capability boundary.

## SKILL.md compatibility

The following Agent Skills concepts remain portable:

- YAML frontmatter with name and description.
- Optional license, compatibility, metadata, and allowed-tools fields.
- Markdown instructions.
- scripts/ for executable helpers.
- references/ for supporting documentation.
- assets/ for static resources.
- progressive disclosure.

The Agent Behavior runtime adds semantic ownership: every discovered Action belongs to a specific Agent, while the root Skill belongs to the Agent itself.

## Recommended Action structure

    actions/
    └── create-order/
        ├── SKILL.md
        ├── scripts/
        ├── references/
        └── assets/

An Action Skill SHOULD describe:

- when the Action applies;
- required evidence;
- inputs and preconditions;
- decisions;
- execution;
- outputs and postconditions;
- recovery;
- failure modes.

## Why actions/ instead of skills/

This is not cosmetic.

Agent Skills uses Skill as the portable unit of reusable expertise.

Agent Behavior uses Action as the executable unit and Skill as its behavioral definition.

Renaming the directory makes the semantic ownership explicit while keeping the underlying SKILL.md format interoperable.

## Progressive disclosure

Metadata should be discoverable cheaply. The full Action Skill should load only when the Action is relevant. Supporting resources should be loaded only when required.

This preserves the context-efficiency model of Agent Skills.
