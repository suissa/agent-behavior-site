---
title: Agent Skills and Actions
description: Understand the difference between a behavioral Skill, an executable Action, and their semantic source.
---

Agent Skills provides a portable file primitive: a directory centered on SKILL.md with optional scripts, references, and assets.

Agent Behavior keeps that primitive but changes the semantic ownership.

## Skill, Action, Agent

    Behavior Flow
         │
         ├──→ Agent SKILL.md
         │
         └──→ Action
                 └──→ Action SKILL.md

The distinction is:

    Skill = behavioral definition / portable projection
    Action = executable capability boundary
    Agent = semantic execution unit

## Agent Skill

Every semantic Agent has one root Agent Skill.

The root SKILL.md is derived from the Agent's Behavior Flow and describes durable behavior across the Agent's capabilities.

It should cover scope, evidence, decisions, invariants, recovery, escalation, and expected outcomes.

## Action Skill

An Action directory contains its own SKILL.md and describes one executable capability.

    actions/
    ├── create-order/
    │   └── SKILL.md
    └── cancel-order/
        └── SKILL.md

An Action Skill should define applicability, inputs, preconditions, decisions, execution, postconditions, recovery, and prohibited outcomes.

## Why actions/ instead of skills/

This is semantic, not cosmetic.

Agent Skills uses Skill as the reusable unit.

Agent Behavior uses Action as the executable unit and Skill as the behavioral representation of that unit.

The directory name therefore expresses ownership:

    Agent
      └── actions/
             └── Action
                    └── SKILL.md

## Progressive disclosure

The file mechanics remain compatible with Agent Skills:

- YAML frontmatter;
- required name and description;
- optional license, compatibility, metadata, allowed-tools;
- scripts/;
- references/;
- assets/;
- progressive disclosure.

See the Agent Skills specification for the portable file contract.

## Do not create two sources of truth

The semantic source is the Behavior Flow.

The Skill is its portable projection.

An implementation should therefore prefer:

    change Behavior Flow
          ↓
    validate semantics
          ↓
    regenerate Skill

over independently editing a generated Skill until it disagrees with the semantic model.
