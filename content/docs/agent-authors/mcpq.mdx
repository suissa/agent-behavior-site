MCPQ is the communication boundary of an Agent.

The important semantic distinction is:

    MCPQ
      ├── Queue semantics for Agent work
      └── MCP interoperability when required

A channel defaults to Queue.

## Minimal configuration

    {
      "$schema": "https://github.com/suissa/agent-behavior-site/blob/main/public/schemas/1.0.0/mcpq.schema.json",
      "channels": {
        "orders": {
          "type": "queue"
        }
      }
    }

## Queue is the default

Queue is the default because the Agent is an asynchronous Actor.

Work may need to:

- remain durable after a process or connection failure;
- retry;
- wait;
- resume;
- fan out;
- be delegated;
- enter human healing.

A caller should not have to keep a request open while the Agent is performing durable work.

## Channel semantics

A Queue channel may declare:

- delivery guarantees;
- ordering;
- retry;
- acknowledgement;
- leases or visibility;
- dead-letter handling;
- correlation and causation;
- idempotency;
- expiry or cancellation when supported.

The runtime MUST NOT advertise a guarantee it cannot actually enforce.

## MCP mode

An MCP channel binds the Agent boundary to MCP.

MCP remains authoritative for protocol semantics, capabilities, transports, authorization, and lifecycle.

MCPQ does not redefine MCP.

## MCP Tasks

The current MCP Tasks extension (io.modelcontextprotocol/tasks) supports durable task handles, deferred result retrieval, progress states, cancellation, and input-required flows.

An Agent runtime MAY map a long-running MCP operation to an internal Queue, provided the MCP wire semantics and authorization context remain intact.

## Human healing

Human healing is naturally represented as a Queue boundary:

    Agent
      │
      ▼
    human-healing queue
      │
      ▼
    Human decision / correction
      │
      ▼
    resumed Behavior Flow

The Queue carries correlation and authorization context needed for safe continuation rather than exposing unrelated secrets.

## Failure isolation

A broken channel MUST NOT disable independent channels or Actions when the runtime can isolate the failure.

Authentication or connection failure affects the corresponding channel unless Agent policy explicitly makes it required.
