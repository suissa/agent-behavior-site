title: Agent manifest

The root manifest is agent.json.

## Minimal manifest

    {
      "$schema": "https://github.com/suissa/agent-behavior-site/blob/main/public/schemas/1.0.0/agent.schema.json",
      "name": "support-agent",
      "version": "1.0.0"
    }

The manifest answers: "Which Agent package is this?"

It does not answer the full behavioral question. That belongs to the Behavior Flow and its derived SKILL.md.

## Metadata

| Field | Purpose |
| --- | --- |
| name | Stable Agent identifier. |
| version | Agent package version. |
| description | Short purpose statement. |
| author | Package authorship. |
| homepage | Documentation or project homepage. |
| repository | Source repository. |
| license | License identifier. |
| keywords | Discovery metadata. |
| runtime | Runtime compatibility metadata. |
| extensions | Runtime-specific metadata under explicit extension namespaces. |

The schema is deliberately closed at the top level. Runtime-specific data belongs under extensions rather than arbitrary fields.

## Fixed semantic projections

| Semantic responsibility | Portable location |
| --- | --- |
| Agent identity | agent.json |
| Agent behavior | SKILL.md |
| Actions | actions/ |
| Knowledge | knowledge/ |
| Communication | mcpq.json |

The root SKILL.md is derived from the Agent's Behavior Flow.

## Package containment

Every package path MUST resolve inside the Agent root. A manifest, Skill, Action resource, or extension that attempts to escape the package boundary MUST be rejected or isolated according to the applicable component failure rule.

## Versioning

The Agent package version and specification version have different purposes.

The specification version defines the package contract.

The Agent version identifies a particular semantic Agent package release.

Agents SHOULD use Semantic Versioning for the Agent version.
