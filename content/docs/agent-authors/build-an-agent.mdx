---
title: Build an Agent
description: Create a portable Agent package with an Agent Skill, Actions, knowledge, and MCPQ channels.
---

An Agent package is a directory whose root identifies one executable Actor.

## Minimal package

    my-agent/
    ├── agent.json
    ├── SKILL.md
    └── actions/
        └── hello/
            └── SKILL.md

agent.json identifies the package. The root SKILL.md defines the Agent's durable behavior. Each directory below actions/ defines one executable capability.

## Add communication

    my-agent/
    ├── agent.json
    ├── SKILL.md
    ├── actions/
    │   ├── hello/
    │   │   └── SKILL.md
    │   └── summarize/
    │       └── SKILL.md
    └── mcpq.json

MCPQ channels are optional. When present, Queue is the default channel mode.

## Add persistent knowledge

For Agents that learn from experience, use:

    knowledge/
    ├── evidence/
    ├── wiki/
    └── evolution/

Keep evidence and wiki state separate from active SKILL.md files. A learned change should pass a validation gate before it becomes active behavior.

## Agent-level SKILL.md

The root skill should describe durable behavior, not a list of every tool.

    ---
    name: support-agent
    description: Resolves customer support requests while preserving evidence, authorization, and escalation boundaries.
    ---

    # Support Agent

    State the Agent's scope, evidence requirements, decisions, execution principles, recovery rules, and failure boundaries.

## Action-level SKILL.md

Actions are where executable capability becomes concrete.

An Action should define its trigger, inputs, preconditions, decision rules, observable execution, postconditions, recovery, and prohibited outcomes.

The format remains compatible with the Agent Skills SKILL.md mechanics.

## Authoring rule

Do not duplicate the same behavioral contract in the Agent Skill and every Action. The Agent Skill defines global behavior; an Action defines capability-specific behavior. Shared references belong in references/ or the persistent knowledge layer when they are learned artifacts.

## Validation

Before publishing:

1. Validate agent.json.
2. Validate the root SKILL.md using Agent Skills-compatible rules.
3. Validate every Action independently.
4. Validate mcpq.json when present.
5. Run representative trajectories through the configured validation gate.
6. Confirm rejected evolution proposals remain in knowledge/evolution/ rather than silently disappearing.
