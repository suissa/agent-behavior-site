---
title: Build an Agent
description: Create a portable Agent package from a semantic Behavior Flow with a derived Agent Skill, Actions, Knowledge, and MCPQ.
---

An Agent package is the portable filesystem projection of one semantic Agent.

The semantic source may begin as:

    Intent
      ↓
    Behavior Flow
      ├── AtomicSkill
      ├── AtomicBehavior
      └── Actions

The package exposes that model through fixed locations.

## Minimal package

    my-agent/
    ├── agent.json
    ├── SKILL.md
    └── actions/
        └── hello/
            └── SKILL.md

agent.json identifies the Agent.

The root SKILL.md is the Agent Skill derived from the Behavior Flow. It is the portable behavioral projection, not an unrelated prompt.

Each directory below actions/ defines one executable Action and contains its Action Skill.

## Add communication

    my-agent/
    ├── agent.json
    ├── SKILL.md
    ├── actions/
    │   ├── hello/
    │   │   └── SKILL.md
    │   └── summarize/
    │       └── SKILL.md
    └── mcpq.json

MCPQ channels are optional. When present, a channel defaults to Queue.

## Add persistent knowledge

For Agents that learn from experience:

    knowledge/
    ├── evidence/
    ├── wiki/
    └── evolution/

Keep Evidence and Wiki state separate from active Skills.

The normal evolution path is:

    Trajectory
      ↓
    Evidence
      ↓
    Wiki
      ↓
    Proposal
      ↓
    Validation
      ↓
    Behavior Flow change
      ↓
    regenerate Skill

A learned change should pass a validation gate before it becomes active behavior.

## Agent-level SKILL.md

The root Skill should describe durable Agent behavior, not a list of every tool.

    ---
    name: support-agent
    description: Resolves customer support requests while preserving evidence, authorization, and escalation boundaries.
    ---

    # Support Agent

    State the Agent's scope, evidence requirements, decisions, invariants, execution principles, recovery rules, and expected outcomes.

The root Skill name MUST match agent.json name.

## Action-level SKILL.md

Actions are executable capabilities.

    actions/
    └── create-order/
        └── SKILL.md

The Action Skill name MUST match the Action directory name.

An Action should define its trigger, inputs, preconditions, decision rules, observable execution, postconditions, recovery, and prohibited outcomes.

The file mechanics remain compatible with Agent Skills.

## Validation

Before publishing:

1. Validate agent.json.
2. Validate the root SKILL.md using Agent Skills-compatible frontmatter rules.
3. Validate each Action independently.
4. Validate mcpq.json when present.
5. Confirm the Agent Skill is traceable to its Behavior Flow source and version when semantic provenance is available.
6. Run representative trajectories through the configured validation gate.
7. Confirm rejected evolution proposals remain in knowledge/evolution/ rather than silently disappearing.
